# 第一章 数据结构基础

## 1. 数据结构在讲什么？

数据结构研究如何组织数据、数据元素之间存在什么关系，以及如何对数据进行操作。

简单来说，就是将现实世界的问题转化为计算机能够存储和处理的数据。

## 1.1 数据结构的基本概念

### 1.1.1 基本概念

- **数据**：描述客观事物的符号记录，是计算机加工处理的对象。
- **数据元素**：数据的基本单位，通常作为一个整体进行考虑。
- **数据项**：组成数据元素的最小单位。
- **数据对象**：具有相同性质的数据元素的集合，是数据的一个子集。
- **数据结构**：相互之间存在一种或多种特定关系的数据元素的集合。
- **数据类型**：一组值及其对应操作的集合。
- **抽象数据类型（ADT）**：对数据对象、数据关系及相关操作的抽象描述。

### 1.1.2 数据结构的三要素

#### 1. 逻辑结构

描述数据元素之间的逻辑关系。

- **集合结构**：数据元素之间除属于同一集合外，没有其他特殊关系。
- **线性结构**：数据元素之间存在一对一的线性关系。
- **树形结构**：数据元素之间存在一对多的层次关系。
- **图状结构（网状结构）**：数据元素之间存在多对多的关系。

#### 2. 存储结构（物理结构）

描述数据元素及其关系在计算机中的存储方式。

- **顺序存储**：逻辑上相邻的元素在物理位置上也相邻。
- **链式存储**：通过指针等方式表示元素之间的逻辑关系。
- **索引存储**：建立索引表，通过索引信息查找数据。
- **散列存储（Hash 存储）**：利用散列函数计算存储位置。

存储结构会影响存储空间的分配、数据运算的实现方式以及运算效率。

#### 3. 数据的运算

数据运算包括对数据进行的各种操作。

- **运算的定义**：针对逻辑结构，规定运算的功能。
- **运算的实现**：针对存储结构，确定运算的具体实现步骤。

### 1.1.3 数据类型与抽象数据类型

#### 数据类型的分类

- **原子类型**：其值不可再分，例如 `int`、`char`、`bool`。
- **结构类型**：其值可以分解为若干成分，例如 C 语言中的 `struct`。

#### 抽象数据类型（ADT）

抽象数据类型是对数据对象、数据关系及相关操作的抽象描述，强调数据的逻辑特性，而不依赖于具体的存储实现。

例如，栈可以定义入栈、出栈、判空等操作，底层既可以使用顺序存储实现，也可以使用链式存储实现。

## 1.2 算法的基本概念

### 1.2.1 算法的定义

算法是对特定问题求解步骤的一种描述，是指令的有限序列，其中每条指令表示一个或多个操作。

**程序 = 数据结构 + 算法**

- 数据结构：解决数据如何组织的问题。
- 算法：解决如何处理数据的问题。

### 1.2.2 算法的五个特性

- **有穷性**：算法必须在有限步骤后结束。
- **确定性**：每条指令都必须有确切的含义，相同输入和相同条件下的执行过程应当确定。
- **可行性**：算法中的每条指令都能够通过已有的基本操作实现。
- **输入**：算法可以有零个或多个输入。
- **输出**：算法至少有一个输出。

注意：算法必须具有有穷性，但程序不一定会结束，例如操作系统中的常驻程序。

### 1.2.3 好算法的特质

- **正确性**：能够得到符合要求的结果。
- **可读性**：容易理解和维护。
- **健壮性**：能够合理处理非法输入或异常情况。
- **高效率与低存储量需求**：尽可能减少时间开销和空间开销。

## 1.3 算法的时间复杂度

### 1.3.1 时间复杂度的定义

时间复杂度用于描述算法的执行时间随问题规模 \(n\) 增长的变化趋势。

算法时间开销的评估方式：

- **事后统计**：运行程序并测量实际执行时间，但结果会受到硬件、编程语言、编译器等因素影响。
- **事前估计**：分析算法的基本操作执行次数与问题规模之间的关系。

时间复杂度通常使用渐进表示法描述算法的增长趋势。

### 1.3.2 渐进复杂度表示法

渐进记号用于描述算法的基本操作次数或资源开销随问题规模 \(n\) 增长的趋势。

设算法的执行次数为 \(T(n)\)，常见的渐进记号有：

- **大 O 记号：\(O(g(n))\)**

  表示渐进上界，描述函数增长速度的上界。

- **大 Ω 记号：\(\Omega(g(n))\)**

  表示渐进下界，描述函数增长速度的下界。

- **大 Θ 记号：\(\Theta(g(n))\)**

  表示渐进紧确界，表示函数的增长速度与 \(g(n)\) 同阶，即同时具有相应的渐进上界和下界。

例如，若：

\[
T(n)=3n^2+5n+10
\]

则：

\[
T(n)=O(n^2)
\]

\[
T(n)=\Omega(n^2)
\]

\[
T(n)=\Theta(n^2)
\]

因为当 \(n\) 足够大时，\(n^2\) 项决定了函数的增长趋势。

**注意：**

- \(O\) 表示上界，不应直接等同于最坏时间复杂度。
- \(\Omega\) 表示下界，不应直接等同于最好时间复杂度。
- \(\Theta\) 表示紧确界，意味着上下界具有相同的渐进增长阶。
- 在常规算法分析中，经常使用 \(O\) 表示复杂度的渐进上界，也经常使用 \(\Theta\) 描述准确的渐进增长阶。

### 1.3.3 时间复杂度的分析方法

#### 规则一：忽略常数系数和低阶项

例如：

`T(n) = 3n² + 5n + 10`

其时间复杂度为 `O(n²)`。

#### 规则二：顺序执行的代码

顺序执行的代码分别分析执行次数，最后保留增长最快的项。

例如，两段循环各执行 `n` 次：

```c
for (int i = 0; i < n; i++) {
    // 执行 n 次
}

for (int j = 0; j < n; j++) {
    // 执行 n 次
}
```

总执行次数约为 `2n`，时间复杂度为 `O(n)`。

#### 规则三：嵌套循环

嵌套循环需要分析内外层循环的总执行次数。

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // 执行约 n² 次
    }
}
```

时间复杂度为 `O(n²)`。

#### 规则四：循环变量按固定倍数变化

```c
for (int i = 1; i < n; i *= 2) {
    // ...
}
```

每次循环变量翻倍，执行次数约为 `log₂ n`，时间复杂度为 `O(log n)`。

注意：不能仅根据循环嵌套层数判断时间复杂度，还需要分析循环变量的变化方式和实际执行次数。

### 1.3.4 最好、平均与最坏时间复杂度

- **最好情况**：输入使算法执行最少操作。
- **平均情况**：考虑不同输入情况及其概率后得到的平均操作次数。
- **最坏情况**：输入使算法执行最多操作。

算法分析中经常关注最坏情况，以便评估算法的性能上限，但具体分析哪种情况需要结合算法本身。

## 1.4 算法的空间复杂度

### 1.4.1 空间复杂度的定义

空间复杂度用于描述算法运行过程中所需存储空间随问题规模 \(n\) 增长的变化趋势。

分析时重点关注与问题规模相关的存储空间，尤其是辅助空间，例如额外数组、动态分配的内存和递归调用产生的栈空间。

### 1.4.2 常见空间复杂度

- `O(1)`：常数空间。
- `O(n)`：线性空间。
- `O(n²)`：平方空间。

### 1.4.3 空间复杂度的分析方法

#### 例一：常数空间

```c
int sum = 0;

for (int i = 0; i < n; i++) {
    sum += i;
}
```

只有固定数量的变量，不会因为 `n` 增大而增加变量数量，因此空间复杂度为 `O(1)`。

#### 例二：线性空间

```c
int arr[n];
```

当数组长度随 `n` 增大时，数组占用的空间与 `n` 成正比，因此空间复杂度为 `O(n)`。

#### 例三：递归空间

如果递归调用最多同时存在 `n` 层，那么调用栈可能占用 `O(n)` 的空间。

例如，递归遍历链表时，最深可能产生与链表长度成正比的调用栈空间；使用循环遍历通常只需要 `O(1)` 的辅助空间。

## 1.5 本章总结

### 数据结构的核心内容

- 数据结构的基本概念：数据、数据元素、数据项、数据对象、数据结构、数据类型、ADT。
- 数据结构的三要素：逻辑结构、存储结构、数据运算。
- 算法的基本概念：定义、五个特性、好算法的特质。
- 算法分析：时间复杂度、空间复杂度。

### 核心分析原则

- 时间复杂度关注基本操作次数随问题规模的增长趋势。
- 空间复杂度关注所需存储空间随问题规模的增长趋势。
- 忽略常数系数和低阶项，保留增长最快的项。
- 分析循环时关注实际执行次数，分析递归时还要考虑调用栈空间。
